## 二、E1 · 公式环检测（P0，正确性修复）

### 根因（对接暴露的 3 个正确性问题之一）

阶段一实现里 `DependencyGraph.collectDirty` 的 Kahn 拓扑用 `other === node` 跳过自边——
**自环（`A3=SUM(A1:A3)`）被当作普通节点入度 0**，照常求值：求值器经缓存感知取值源读到
**自身旧值**（120），产生 120→400→490 的**静默漂移**。这比报错危险得多。

### 修复（按任务书要求「建图时标记，不依赖求值时发现」）

1. **自环**：`setFormula` 阶段检测引用区间是否覆盖自身坐标 → `node.selfCycle = true`
   → 立即落 `#CYCLE!`，**绝不执行求值**（求值 = 读旧值 = 漂移根源）；
2. **自环边计入入度**：Kahn 阶段自环 +1 入度 → 永不就绪 → 落入 cyclic（含环下游）；
3. **区间环 / 跨表互引**（`A1=SUM(B1:B2)` ↔ `B1=SUM(A1:A2)`、`Sheet1!A1 ↔ Sheet2!A1`）：
   逐格 `setFormula` 时对受影响子图跑同款 Kahn（批量装载传 `deferCycle` 跳过，由
   `recalculateAll` 最终拓扑统一处理，避免 O(n²) 装载开销）；
4. **#CYCLE! 保真传播**：修复传播断链——此前缓存中的错误实例经 `valueToCell` 字符串化，
   下游 `toNumber` 失败变成 `#VALUE!`；现在取值源**原样透传 FormulaError**，
   SUM/AVERAGE/MIN/MAX 传播区间内首个错误（Excel 语义）；
5. **附带能力**：解析器支持整列区间 `A:A` / `Sheet1!A:A`（顺带修复其词法/语法缺口）。

### 验收对照（任务书 E1）

| 要求 | 结果 |
|------|------|
| 自环 → `#CYCLE!`，不参与数值传播 | ✅ `cycle.test.ts`「A3=SUM(A1:A3) 建图即 #CYCLE!」+ 漂移回归测试（3 轮上游变更均保持 #CYCLE!） |
| 区间环（双向/跨表）→ 环上全部 #CYCLE! | ✅ 双向环、三节点环、跨表互引用例全绿 |
| 建图时标记，recompute 跳过 | ✅ setFormula 阶段完成（含解环恢复用例：改掉公式即恢复数值） |
| 下游引用环格传播 #CYCLE! | ✅ A4=A3*2 → A5=A4+1 全链 #CYCLE!；且环不污染无关列（隔离性用例） |

## 三、E2 · 依赖图空间索引（P2）

`RectIndex`：STR 批量装载 R-Tree（O(n log n) 建树）+ **超大区间单独线性表**
（整列引用会把节点 MBR 撑到退化，超过行 4096/列 256 阈值不进树）。懒重建：公式格
增删（低频）只标脏，下次查询整树重建——值编辑（高频）零成本。

`collectDirty` 三次查询（seeds / 下游扩散 / 拓扑前置）全部走索引；接口签名不变。

### 基准（200 变更格的 collectDirty 查询阶段；内联复刻旧算法做同机同数据对照）

| 公式数 | 线性扫描（旧） | 空间索引（新） | 加速 |
|--------|--------------|--------------|------|
| 1,000 | 9.3–11.4ms | 0.5–1.1ms | **13–25×** |
| 10,000 | 21.6–75.7ms | 2.0–8.5ms | **8–17×** |
| 50,000 | 165–245ms | 20–52ms | **5–11×** |

（多轮测量有波动，取值范围如实列出；正确性用例：索引查询结果与线性扫描逐一比对一致。）
结论：≤5000 公式（阶段一已够用）→ **5 万公式量级的增量调度成本降至两位数毫秒**。

## 五、E4 · 编辑器弹出层挂载（P1，对接刚需）

- `PopupHostManager`（grid 包，spreadsheet 复用）三级宿主解析：
  `setPopupHost(element)` 显式指定 > `editorHostMode: 'body'`（引擎在 body 建
  fixed 全屏覆盖层，pointer-events:none）> 默认 inline（root 内，原行为）；
- **坐标换算**：脱离 root 的宿主自动把单元格矩形换算成视口坐标
  （rootRect + cellRect）；页面滚动/窗口缩放自动跟随重定位（capture 监听，编辑期挂载）；
- **语义不变**：IME 守卫、commit/cancel、校验、undo 全链路不受影响（测试验证编辑器
  在 body 宿主内且坐标含 rootRect 偏移）；
- **验收对照**：remote-search 下拉在底部边缘行打开不再被裁切（宿主不在 root 内，
  overflow 无关）——jsdom 用例验证挂载位置与坐标；视觉验收在 C3 页面确认。
- 引擎销毁时自动移除 body 覆盖层与监听。

## 六、E5 · 填充序列（P2）

`deriveFillSeries`（grid 包，spreadsheet 复用）分类推导，顺序经过实测校准：

1. **日期候选优先**（ISO 字符串或 ≥20000 的整数码）——⚠️ 实测教训：序号日期本质是
   number，若数字等差分支先行，`01-31 → 02-28` 会被「步长 28」截获；单值日期退回复制；
2. **中文循环表**（单值也命中，默认步长 +1）：周一~周日、星期一~日、一月~十二月（含正月/腊月变体）、一~十；
3. 单值复制；多值数字等差（步长 = 相邻差，支持上/左拖反序）；其余平铺。

**验收对照**（任务书用例全过）：`1,3 → 5,7,9` ✓；`01-31 下拉月 → 02-28 → 03-31`（锚定日取
首格，钳制不污染后续月份）✓；`周一 → 周二…周日循环` ✓。公式格线退回平铺（引用平移 v2）。

## 十、实现过程中发现并修复的真问题（测试驱动）

1. **区间环漏检的深层原因**：Kahn 自边被跳过（E1 主因）+ ref 条目被插进「公式所在表」
   而非「引用目标表」的索引（跨表互引场景）——两个都由 E1 用例抓出；
2. **错误传播断链**：缓存错误实例 → 字符串化 → 下游 #VALUE!（应为 #CYCLE! 保真）；
3. **拓扑入度方向弄反**（重构时引入）：「覆盖某格的节点」是下游不是前置——靠既有
   回归测试当场抓回；
4. **E5 分类顺序**：数字等差分支截获日期序号（46109 vs 46112）——靠任务书用例抓出；
5. **E6 移动基准**：以焦点格为基准在「编辑前选区不在编辑格」场景下错误——改为以
   编辑格为基准。
