# SheetX 引擎使用与对接指南（UI 开发者专用）

> 版本：v1.0 · 日期：2026-11-20 · 面向：`@sheetx/web-component` / `vue` / `react` / playground 的 UI 开发者
> 引擎状态：T1-T11 全部实现，148 测试全绿。本指南覆盖你需要的全部接口、事件、契约与注意事项。

## 〇、五分钟上手

引擎已发布形态为 **workspace 源码直连**（包的 `main` 直接指向 `src/index.ts`，Vite 天然支持，无需构建产物）。

```ts
// 最小 Grid（业务数据网格）
import { createGrid } from '@sheetx/grid'

const grid = createGrid({
  container: '#grid-host',          // 容器必须有确定尺寸（引擎 100% 填充）
  columns: [
    { key: 'name',  title: '商品名称', width: 180 },
    { key: 'qty',   title: '数量',    width: 100, editor: 'number', editable: true },
    { key: 'price', title: '单价',    width: 100, editor: 'currency' },
  ],
  data: [
    { name: '苹果', qty: 100, price: 5.5 },
    { name: '香蕉', qty: 200, price: 3.2 },
  ],
  features: { clipboard: true, undoRedo: true, editing: true },
})

grid.on('cell-change', (tx) => console.log(tx.changes))
grid.setValue('自动生成的行 id', 'qty', 50)   // 见下文「行 id」说明
await grid.undo()
```

```ts
// 最小 Spreadsheet（电子表格，公式可用）
import { createSpreadsheet } from '@sheetx/spreadsheet'

const sheet = createSpreadsheet({
  container: '#sheet-host',
  sheets: [{ name: 'Sheet1', rowCount: 200, columnCount: 26 }],
  features: { formula: true },
})
sheet.setCellValue(undefined, 0, 0, 100)          // A1 = 100
sheet.setCellValue(undefined, 1, 0, '=A1*2')      // B1 = 公式，自动增量重算
sheet.on('formula-change', (changes) => console.log(changes))
```

## 一、包地图（依赖方向）

```
UI 阶段开发 →  @sheetx/web-component（Lit 外壳）
           →  @sheetx/grid        createGrid        业务网格模式
           →  @sheetx/spreadsheet createSpreadsheet 电子表格模式

模式层依赖的引擎层（UI 一般不直接碰）：
  data / renderer / interaction / editors / formula / validation / data-adapter / io / themes
  契约全部在 @sheetx/core（types/command/event/plugin/renderer/lifecycle/EventBus）
```

规则：UI 层只 import `@sheetx/grid` / `@sheetx/spreadsheet` / `@sheetx/themes` / `@sheetx/io`（按需）；不要从 interaction/editors 直接改引擎内部状态（编辑器注册等扩展点除外，见 §4）。

## 二、公共 API 参考

### 2.1 SheetXGrid（`@sheetx/grid`）

**创建**：`createGrid(config: GridConfig)` 或 `new SheetXGrid(config)`

```ts
interface GridConfig {
  container: HTMLElement | string          // 必填
  columns: GridColumnDef[]                 // 必填
  data?: UnknownRecord[]                   // 缺省空表
  adapter?: IDataAdapter                   // 缺省 LocalAdapter
  features?: {
    clipboard?: boolean                    // 默认 true
    undoRedo?: boolean                     // 默认 true
    rowSelection?: boolean                 // 默认 true
    editing?: boolean                      // 默认 true（总开关）
    showRowNumbers?: boolean               // 默认 true
    strictValidation?: boolean             // 默认 true：error 级校验失败阻止提交
  }
  rowHeight?: number                       // 默认 28
  colWidth?: number                        // 默认 100
  theme?: 'light' | 'dark' | ThemeTokens   // 默认 light
  debug?: boolean                          // 默认 false；true 开启脏矩形红框可视化
}
```

```ts
interface GridColumnDef extends ColumnDef {   // ColumnDef 来自 core
  key: string; title: string
  width?: number                              // 缺省 100
  editor?: string                             // 编辑器名（见 §4），缺省按值类型推断
  editable?: boolean                          // 缺省 true
  formatter?: string                          // 格式化器名（见 §5）
  frozen?: boolean                            // 冻结列（必须从第 0 列连续出现）
  editorParams?: UnknownRecord                // 传给编辑器的参数（见 §4）
}
```

**数据 API**（全部走 mutation，可撤销、有事件）：

| 方法 | 说明 |
|---|---|
| `getValue(rowId, field): unknown` | 读 |
| `setValue(rowId, field, value)` | 写（source='api'，可撤销） |
| `setData(records)` | 全量替换（可撤销） |
| `getData(): UnknownRecord[]` | 导出 |
| `insertRows(index, records)` / `deleteRows(rowIds)` | 结构变更（可撤销，undo 恢复位置与数据） |
| `getRowIndex(rowId)` | 行 id → 下标 |
| `validate(): Promise<ValidationError[]>` | 全表校验（保存前） |
| `undo() / redo() / canUndo() / canRedo()` | 历史 |
| `getSelectedRanges()` / `getSelectedRows()` / `getSelectedFieldValues(field)` | 选区 |
| `scrollToCell(row, col)` / `setColumnWidth(col, width)` / `freezeRows(n)` | 视图 |
| `registerFormatter(name, fn)` / `registerEditor(name, factory)` | 扩展点 |
| `setTheme(theme)` / `refresh()` / `getRenderStats()` / `on/once/off` / `destroy()` | 其他 |

**⚠️ 行 id 说明**：引擎要求每行有稳定唯一 id。宿主数据有 `id` 字段（或通过 LocalAdapter.fromRecords 指定 idField）则直接用；**没有 id 会自动生成但不稳定**——生产环境务必给业务主键。`getValue`/`setValue` 用 rowId；下标会随插删漂移，禁止把下标当身份存起来。

### 2.2 SheetXSpreadsheet（`@sheetx/spreadsheet`）

```ts
createSpreadsheet({
  container, sheets: [{ name, rowCount, columnCount, cells? }], activeSheetName?,
  features: { formula: true, clipboard: true, undoRedo: true, editing: true },
  theme, rowHeight, colWidth,
})
```

| 方法 | 说明 |
|---|---|
| `getCellValue(sheetNameOrId?, row, col)` | 读（公式格返回**计算值**；错误显示 `#DIV/0!` 等） |
| `setCellValue(sheetNameOrId?, row, col, value)` | 写。字符串以 `=` 开头 → 自动按公式处理 |
| `setCellStyle(sheetNameOrId?, range, style \| null)` | 样式（bold/color/background/hAlign/numFmt/border…） |
| `mergeCells / unmergeCells` | 合并（可撤销） |
| `addSheet(name?)` / `removeSheet(id)` / `setActiveSheet(id)` / `getSheetIds()` | 工作簿结构 |
| `recalculateAll()` | 快照加载后手动触发全量重算 |
| 其余 | undo/redo/getSelectedRanges/on/destroy 同 Grid |

### 2.3 公共事件（`PublicEvent` 常量名）

| 事件 | 载荷 | 说明 |
|---|---|---|
| `cell-change` | Grid：`DataTransaction{changes: CellChange[]}`；Sheet：`SheetTransaction{sheetId, changes: SheetCellChange[]}` | 数据变化（用户编辑/API/粘贴/撤销均触发） |
| `selection-change` | `{ranges: CellRange[], activeIndex}` | 选区变化（不进 undo） |
| `before-edit`（Grid）/ `before-cell-edit`（Sheet） | `{rowId/row, col, value, cancel()}` | **可取消**——监听器调 `cancel()` 阻止进入编辑（ERP 拦截点） |
| `after-edit` | `{rowId, field, row, col, oldValue, newValue, committed}` | 编辑关闭后（含被校验拦截的 committed=false） |
| `validation-error` | `{errors: ValidationError[]}` | 校验失败 |
| `formula-change`（Sheet） | `FormulaChange[]` | 公式增量重算结果 |
| `sheet-added` / `sheet-removed` / `active-sheet-changed`（Sheet） | `{sheetId…}` | 工作簿结构，供 sheet tabs UI |
| `sx:*`（sx:resized 等） | — | 内部诊断事件，可订阅但勿依赖 |

**Web Component 桥接建议**：wrapper 监听引擎事件 → `dispatchEvent(new CustomEvent('sx-cell-change', {detail: payload, bubbles: true, composed: true}))`。方向键/Enter 等 UI 内部导航事件不要转发到引擎外。

## 三、渲染器与自定义绘制（一般不需要，扩展时看）

引擎内部管线：场景构建器产出**纯数据绘制指令**（`DrawCommand`：rect/text/line/polyline/clip）→ RenderScheduler（rAF 合帧）→ Canvas2DRenderer（脏区域 + 滚动位块搬移 + HiDPI）。

- UI 层**不要**直接操作 canvas；视觉定制走主题（§6）。
- 需要新增绘制能力（如迷你图/条件格式图标）：参考 `grid/src/scene/grid-scene-builder.ts` 的 pass 结构，新增指令类型提 issue 进 core/renderer。
- 帧率验收：`grid.getRenderStats()` → `{fps, lastRenderMs, drawCalls, blitFrames}`；`blitFrames > 0` 说明滚动位块搬移生效。

**后台渲染（可选加速层）**：`@sheetx/renderer` 的 `OffscreenRenderer` 把整帧绘制搬进内联 Worker（`transferControlToOffscreen`），主线程只负责构建场景与提交帧：

```ts
import { OffscreenRenderer, isOffscreenRendererAvailable } from '@sheetx/renderer'
const renderer = new OffscreenRenderer() // 能力检测不满足时自动降级为 Canvas2DRenderer（mode === 'main'）
renderer.initialize(canvasEl)
renderer.resize(width, height)
renderer.render(scene)                    // 提交帧，异步绘制
const stats = await renderer.waitForStats() // { lastRenderMs, drawCalls, sample }
```

- `renderer.mode` 为 `'worker'` 表示真的在后台线程绘制；`sample` 是画布中心像素回传，可用于自动化验收。
- 注意：`render()` 是「提交帧」语义（异步）；脏矩形/滚动位块搬移仍由主线程 `Canvas2DRenderer` 提供，后台模式以「绘制不阻塞主线程」为价值点。
- 一条 canvas 只能 `transferControlToOffscreen()` 一次；已被主线程 `getContext('2d')` 的画布会走降级，不会抛错。

## 四、编辑器系统（UI 定制主战场之一）

### 4.1 内置编辑器与参数（`ColumnDef.editor` + `editorParams`）

| 编辑器名 | 参数 | 提交值 |
|---|---|---|
| `text` | — | string |
| `multiline` | — | string（Enter 换行，Ctrl+Enter 提交） |
| `number` | `{precision?, min?, max?}` | number（非法输入保持打开红框，不静默写错值） |
| `currency` | `{symbol?, precision?, min?, max?}` | number（显示 ¥ 千分位） |
| `date` / `datetime` | — | `'yyyy-MM-dd'` / ISO 串（原生控件） |
| `select` | `{options: (string\|{label,value})[], multiple?}` | value 或 value[]（↑↓ 导航、输入筛选） |
| `boolean` / `switch` | — | boolean（点击即提交） |
| `remote-search` | `{query(keyword): Promise<RemoteSearchItem[]>, minChars?, debounceMs?, emptyText?}` | item.value；**item.payload 作为联动字段同一事务填充**（ERP 商品选择场景：选编码自动填名称/规格/价格） |

### 4.2 自定义编辑器契约

```ts
grid.registerEditor('my-editor', (ctx: EditorContext): EditorHandle => {
  const el = document.createElement('div')
  // ctx: {row, col, rowId, field, value, displayValue, rect, container,
  //       imeGuard, params, commit(value, autofill?), cancel()}
  return {
    el,
    mount() { el.focus() },        // 元素进入 DOM 后调用——此时才能 focus
    focus() { el.focus() },
    destroy() { el.remove() },     // 移除自身监听
  }
})
```

**三条铁律**（违反 = 中文输入出问题）：
1. 编辑器内创建的输入元素**必须** `ctx.imeGuard.attach(input)`；
2. Enter/Esc 处理前必须 `ctx.imeGuard.shouldSuppressKeyEvent(event)`，true 则吞掉；
3. 编辑器不写数据——只能 `ctx.commit(value, autofill?)` / `ctx.cancel()`，写值/校验/undo 全由引擎命令系统完成。

### 4.3 弹层与焦点（UI 需要知道的坑）

- 编辑器宿主在引擎 root 内（`pointer-events:none`，子元素 auto）——**v1 弹层越出表格边界会被 root 裁切**。v2 提供弹出层挂载 API + Floating UI；v1 请把下拉列表高度控制在容器内，或与引擎侧协商把 editorHost 提升到 body（改动点已预留）。
- 焦点：引擎 root `tabIndex=0`，鼠标按下自动回焦（`preventFocusLoss`）。编辑器打开时焦点在编辑器输入上，键盘归编辑器（状态机 `EDITING` 守卫），提交后自动回到表格导航。
- 方向键在 `select` 编辑器里是移动选项**不是移动单元格**——编辑器内部已拦截，这正是正式方案 L1113-1119 的要求。

## 六、主题（双出口，务必理解）

| 出口 | 形态 | 谁消费 |
|---|---|---|
| **Canvas 色板** | `ThemeTokens` TS 对象（引擎内部直接取色） | 表格画布 |
| **CSS 变量** | `--sx-color-*` / `--sx-font-*`（引擎自动注入到 root 元素） | 编辑器/菜单/弹层 DOM、你的 Lit 组件 |

```ts
grid.setTheme('dark')            // 一次调用：canvas 重绘 + CSS 变量刷新
applyTheme(element, 'light')     // UI 组件库给任意子树注入（@sheetx/themes）
themeToCssText(darkTheme, ':root') // 生成 <style> 块（全局注入用）
```

自定义主题：`new ThemeRegistry(); registry.register({name:'brand', ...tokens})` → `setTheme('brand')`。
**注意**：canvas 读不了 CSS 变量，所以你的 Lit 组件和表格若要联动换肤，两边都要走 `setTheme`/`applyTheme`（引擎已保证一致性）。

## 七、Web Component / Vue / React 适配层配方

### 7.1 Lit wrapper（web-component 包）建议结构

```ts
@customElement('sheetx-grid')
export class SheetXGridElement extends LitElement {
  @property({type: Object, attribute: false}) columns?: GridColumnDef[]   // 数据对象禁止走 attribute
  @property({type: Object, attribute: false}) data?: UnknownRecord[]
  @property() theme?: string                    // 简单配置走 attribute（'dark'）

  /** 引擎实例持有为普通私有字段——绝不进 Lit 响应式系统（研究报告 §07 结论） */
  private engine: SheetXGrid | null = null

  connectedCallback() {
    super.connectedCallback()
    this.engine = createGrid({
      container: this.renderRoot.querySelector('.host')!,   // 或 light DOM 容器
      columns: this.columns ?? [], data: this.data ?? [], theme: this.theme,
    })
    // 事件桥接：引擎事件 → CustomEvent(bubbles+composed)
    this.engine.on('cell-change', (tx) => {
      this.dispatchEvent(new CustomEvent('sx-cell-change', {detail: tx, bubbles: true, composed: true}))
    })
  }

  disconnectedCallback() {
    super.disconnectedCallback()
    this.engine?.destroy()      // v1 简单策略：断连即销毁，重连重建（实例级 attach/detach 是引擎 v2 项）
    this.engine = null
  }

  render() { return html`<div class="host" style="width:100%;height:100%"></div>` }
}
```

### 7.2 三个已知的 tsconfig/打包坑（研究报告 §07 + Lit 研究结论）

1. **Lit tsconfig**：`"experimentalDecorators": true, "useDefineForClassFields": false`——项目 target ES2022+ 时后者默认翻转 true，会静默毁掉 Lit 属性响应性（不报错！）。web-component 包必须显式设置。
2. **不要把 lit 打包进发布产物**：lit 作为 dependency 声明；import 带文件扩展名。
3. **引擎包不要打包**：workspace 源码直连 + `sideEffects: false` 已就绪，适配层保持同样纪律（tree-shaking 才有效）。

### 7.3 Vue / React

- Vue：直接用 `<sheetx-grid>` 自定义元素（Vue 3 对 CE 友好），或薄壳组件 `onMounted → createGrid`、`onBeforeUnmount → destroy`。
- React：`useRef + useEffect`（严格模式双调用注意：effect 清理函数里 destroy，重跑时重建）。

## 九、已知限制（对接时避免踩坑）

1. **冻结行**：`freezeRows(n)` API 已有，但滚动绘制 v1 按「无冻结行」处理（冻结列完整可用）。需要冻结行效果请先用冻结列方案，冻结行在引擎 v1.1 补齐（9 视口绘制已在规划）。
2. **弹层裁切**：见 §4.3——下拉列表高度限制在表格容器内。
3. **编辑后焦点移动**：提交后焦点格不动（Excel 是 Enter 下移）——UI 层可在 `after-edit` 后调 `scrollToCell`/ selection API 补齐，引擎 v2 内建。
4. **填充柄序列**：v1 是重复平铺，无日期/等差/中文星期推导。
5. **粘贴自动扩行**：v1 越界截断（不自动插行）。
6. **性能基准的边界**：引擎逻辑层基准在 Node 跑（148 测试含 9 项基准）；帧率类指标必须按 §8 在浏览器验收。

## 十、遇到问题的求助路径

1. 先查本指南与《引擎任务完成报告.md》（后者含设计决策与已知 bug 清单）；
2. 运行 `pnpm test`：148 个测试覆盖了数据/公式/交互/布局的核心语义，多数疑问可以先用测试验证行为；
3. 引擎侧接口缺口/契约变更：直接向引擎开发者提（跨包类型必须进 `@sheetx/core`，不允许包内重复定义——任务书 §0 纪律）。
